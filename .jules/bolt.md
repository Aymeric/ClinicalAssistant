## 2026-03-08 - Fast String Trimming vs RegExp Matching for Floating Point Formatting
**Learning:** Calling `RegExp.replaceFirst` for trailing zero and trailing dot cleanup on numeric strings in hot paths (like `formatSensibleNumber`) incurs significant regex engine overhead. Replacing regex matches with backward `codeUnitAt` index inspection and `substring` slicing yielded a ~32.6% speedup (2721ms vs 1833ms over 1,000,000 calls). Conversely, replacing RegExp checks with `double.tryParse` on arbitrary non-numeric strings in Dart VM introduced parser state allocation overhead for non-numeric tokens.
**Action:** Use index-based character inspection (`codeUnitAt`) for character/suffix trimming on strings instead of compiling or invoking regexes, and test string parsing optimizations on non-numeric inputs before committing.
